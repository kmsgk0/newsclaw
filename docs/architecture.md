# 架构与数据关系

NewsClaw 以共享新闻库连接公开阅读、个人编辑、技能和专题，所有事实输出保留来源。私人会话、偏好和阅读成果属于账号，公共管理权限不提供访问他人私人资料的能力。

系统围绕内容完整、中文阅读和个人资料持续维护组织。API 与后台共享业务规则，任务状态可观察且能够恢复。原生移动客户端、外部消息渠道、组织权限、任意代码插件、通用工作流与智能体编排、独立图数据库和全网热度预测不在当前范围内。能力与场景见[规格索引](README.md#能力与场景索引)。

## 应用结构

React Router、TypeScript 和 Tailwind 构成前端，Fastify 提供 API，PostgreSQL 保存数据。远程模型提供摘要、翻译、嵌入与问答，Docker Compose 组织运行服务。API 与 Worker 共用代码和镜像，BullMQ 管理固定业务任务，Redis 使用持久化卷、AOF 和 noeviction。路由负责身份及参数，服务处理业务，Repository 封装查询，外部信源、模型与 MCP 集中在适配层。账号、新闻、编辑、技能和专题按业务职责组织，应用入口负责装配与启停。模块说明见[账号](modules/account.md)、[新闻](modules/news.md)、[编辑与技能](modules/editor.md)和[专题](modules/topics.md)。

## 数据关系

| 对象 | 关系与保存规则 |
| --- | --- |
| 信源与报道 | 信源及规范化 URL 唯一；正文版本与派生结果对应，来源、链接和发布时间独立保留 |
| 新闻与事件 | 多篇报道可属于同一事件；概况、时间线和图谱共用当前关联 |
| 账号与编辑 | 每个账号一位编辑；配置、会话、记忆、个人日报及手记均带账号归属 |
| 技能 | 公共模板与个人副本分别保存；模板变化不覆盖个人修改 |
| 专题 | 自动匹配、手动加入及显式排除共同确定报道；笔记可维护，成果保留生成时正文及来源 |
| 分享 | 主动发布的独立快照只包含选中成果与公共来源，撤销后链接不可读 |
| 日报与手记 | 按所属账号及业务日期保存，同日成功更新保持一份对象，失败保留旧结果 |
| 提醒与任务 | 提醒按用户与报道去重并保留原因；任务保存操作标识、输入版本、状态、结果和尝试记录 |

迁移保持新闻与私人对象标识。内容重处理不清空收藏、专题、会话或成果。业务日期统一使用 Asia/Shanghai；日期字段直接按日期字符串传输。

## 新闻、检索与热点

RSS、Atom、JSON 和网页进入统一报道格式，正文通过主体提取和 Markdown 转换保留标题、段落、列表、引用、表格、代码和有效链接。来源仅有摘要时明确标识，不能以模型扩写替代原文。

语言判断基于实际文本。分类映射到稳定中文领域；摘要保留事实与条件，长文翻译按段落标识检查覆盖。内容更新时保留上一成功版本，逐篇记录失败，其余材料继续处理。管理员可以修改来源配置、查看失败步骤并重处理单篇报道。

关键词检索覆盖原文与中文派生内容，语义检索使用 pgvector。事件候选结合时间、实体和内容，管理员按名称搜索并修正关联。热点以独立来源、报道数和最近时间排序，历史趋势使用独立的多日窗口，所有点来自实际报道统计。

## 编辑执行

读者明确选择新闻、事件、收藏或专题，或进行跨新闻提问。编辑组装设置、明确兴趣、有效记忆和会话上下文，通过 MCP 调用同一新闻服务。来源编号由服务端映射，模型不能自行指定私人访问身份或来源。

显式技能优先，自动选择至多使用一项本人启用技能。五项技能的用途、示例和输出分别定义。双语对照使用实际材料，导图校验结构和来源。SSE 分别传输文本、来源、技能和完成状态；失败保留原问题，重试不重复添加同一问题。启动时恢复中断回答，前端根据实际状态提供继续或重试。

## 个性化与后台任务

个人日报按兴趣和记忆选择当日材料，没有兴趣时使用当日新闻。日报待采集就绪后生成，材料版本变化可以补生成。手记处理上次成功游标后的活动，按实际活动批次建立任务，同日新增活动更新同日手记；手记、记忆及游标共同提交，手动偏好优先。

任务接收将业务、任务和 outbox 放在同一事务，提交后返回 `202`、`taskId`、`status` 和 `statusUrl`。状态查询只读。投递循环使用稳定消息标识，执行标识与代次约束结果写入；已成功任务重复收到时沿用结果。队列中断后核对并补投缺失消息，外部调用在事务外完成。

暂态故障有限退避，最终失败及死信待投递记录共同持久化；死信无自动消费者，管理员仅重放公共任务。任务执行和提交时核对权限及对象状态，旧尝试不能覆盖新内容。实际调用次数如实记录。

### 异步验证

隔离 API、数据库、Redis 和外部替身检查两档上游耗时，每档提交 20 个不同请求，比较提交 P95 与完整执行时间。同时检查停止 Worker 后恢复、提交后确认前中断、重复投递、权限、事务回滚、有限重试与死信。检查时记录提交与完成时间、队列状态、执行次数及数据库结果。用例入口为 `npm run test:api`。

## 接口与工程合同

JSON 响应使用 `code`、`message`、`data` 和 `requestId`。输入错误的 `data.fieldErrors` 将字段路径映射到可读提示。SSE 在开始前返回 HTTP 错误，开始后通过错误事件结束。日志使用单行 JSON，不包含凭据或私人正文。

自动化检查使用隔离数据与可控模型，真实模型内容与数据恢复使用各自的检查材料。完整命令及准备条件见[检查入口](verification/checks.md)。

## 阅读与工作区

页面以功能名称和内容组织，搜索集中在资讯列表，详情返回保留上下文。正文共享 Markdown 渲染和引用映射，长文采用合适行宽。编辑填满可用工作区，输入框保持可操作，窄屏会话列表可折叠。流式输出尊重向上阅读位置。

图谱按连接关系组织布局，选择节点突出相关关系，窄屏提供同数据的列表。表单、弹窗、加载、无内容与错误均有明确反馈；保存成果后提供查看入口，公开分享以实际标题与内容为主。

## 内容与依赖边界

外部内容结构和模型结果需要实际核验；自动检查覆盖结构、来源及失败行为，真实材料检查事实和阅读效果。内容与服务失败保持明确状态及重试入口，私人数据边界在服务端执行。

## 启动与维护

按依赖准备配置、备份数据、执行迁移和初始化，启动 API 与 Worker 后检查健康及主要操作。保留上一可运行镜像，恢复时使用匹配版本与备份，在隔离数据库核对记录、关联及账号访问。具体操作见[运行说明](runtime.md)。
