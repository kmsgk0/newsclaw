# NewsClaw 产品规划

本目录维护产品目标、需求场景、总体设计和实施安排。当前实现入口和已交付能力见[文档导航](../README.md)；本目录保留完整目标与尚未交付的场景。现行行为见 [OpenSpec 规格](../../openspec/specs/)。

## 产品定位

新闻分散在不同来源，读者需要重复查找背景、辨认同一事件的多篇报道，并记住值得跟进的进展。NewsClaw 将资讯整理、个人编辑和持续跟进放在同一条阅读流程中，让回答、简报和可视化结果都能回到来源。

## 功能范围

- 建立公开资讯与账号体系，提供筛选、摘要、翻译、事件聚合、搜索、收藏和阅读记录。
- 每位用户拥有可配置的 AI 编辑，支持带来源的连续问答、MCP 查询、个人日报、可管理的长期记忆和每日编辑手记。
- 提供通俗解读、多源对比、专题简报、思维导图、双语阅读五项技能，支持安装个人副本、修改、启停和发布。
- 提供站内热点、事件时间线、私人专题、笔记、知识图谱、成果保存和可撤销分享；关注更新通过站内消息提醒。
- 建立固定后台任务、统一接口与日志、测试和容器化运行合同。

产品规划包含上述完整能力，实施按依赖与可交付范围分组。原生移动客户端、外部消息渠道、任意代码插件和通用智能体编排不在范围内。

## 技术组成

采用 React Router 前端、Fastify API、共享业务服务和后台 Worker。PostgreSQL 保存公共内容、私人数据、检索数据和任务记录，Redis + BullMQ 管理队列执行；远程模型提供摘要、翻译、嵌入和问答能力。Docker Compose 负责 API、Worker、PostgreSQL 与 Redis 运行，工程合同见[项目规则](../../AGENTS.md)和[工程规范](../standards/)。

架构、数据关系及共享业务约定见[总体设计](design.md)，建议交付顺序与实施任务见[路线图](roadmap.md)。

## 实施与现行规格

开始一轮工作时，从目标需求中选择明确的交付范围，创建对应 OpenSpec 变更并保留需求编号。实现、测试和必要文档按该变更的任务完成，未纳入本轮的目标继续保留在产品规划中。

变更完成并通过规定验证后同步主规格、归档。已交付需求的正文由现行规格维护，产品入口保留编号、摘要和链接；路线图关联相应变更，任务状态在变更中维护。开发方法见[开发指南](../../CONTRIBUTING.md)。
