# 测试规范

## 来源与组织

需求 Scenario 是测试预期的依据。用例标明需求编号，按正常、失败、边界组织，保持从需求到用例和从用例到需求的双向对应。适用的参数非法、权限不足、资源缺失、依赖不可达场景均须覆盖。

单元测试覆盖独立业务规则；接口测试验证身份、响应及数据变化；端到端只覆盖完整阅读、问答和专题主流程。测试数据使用独立数据库，运行前后清理，不依赖执行顺序及残留记录。

外部模型、信源、工具和时钟采用可控制的替身，自动化测试不消耗真实模型服务。真实模型的回答质量、引用与技能效果使用明确样本单独核验，保留输入、可见结果和必要来源。

## 命令与通过判定

实现时提供 `npm test`、`npm run test:api`、`npm run test:e2e`；README 说明配置、启动依赖、报告位置和一键运行方式。格式、类型及构建检查使用 `npm run lint`、`npm run typecheck`、`npm run build`。

用例失败必须非零退出并阻断合入。跳过的用例说明理由和未覆盖范围，未执行不得报告通过。测试报告和临时取证文件不提交 Git。

| 判断 | 预期与核对方式 |
| --- | --- |
| 被当成成功 | 业务拒绝场景不得返回成功业务码或成功完成事件 |
| 被放行 | 未授权调用不能读取私人数据、触发工具或产生写入 |
| 被误拒 | 合法输入和本人资源必须按合同成功处理 |
| 未处理故障 | 不返回堆栈或无信息量的错误；需要请求标识、错误类型和可观察失败状态 |

业务结果按 `code` 判定，同时核对 HTTP 与 [接口合同](backend.md)一致。SSE 逐项检查文本、来源、完成或错误事件。写入场景检查数据库结果，失败场景检查没有不应发生的副作用。不能仅以“不报错”“长度相同”判断行为成立。

## 必须保留的回归

- 新闻去重保留不同来源的独立报道，事件修正同步到查询、时间线与关系图。
- 用户之间的收藏、会话、日报、手记、记忆、消息和专题相互隔离，MCP 使用同样的规则。
- 公共技能变化不覆盖个人副本；停用技能不再自动选择，显式指定不可用技能返回原因。
- 用户明确记忆优先，重复整理不复活同批历史中已删除的记忆。
- 任务中断与重跑不重复创建日报、手记或提醒；模型失败保留已保存成功结果。
- 问答、导图、图谱和分享来源可追溯，分享撤销后内容不可读取。
- 必需配置缺失、依赖失败、健康检查与请求日志符合运行合同。

每项变更新增或调整相关场景用例。修复缺陷先补可复现用例；选择一处关键判断做临时破坏，确认对应测试会失败，随后恢复并确认通过。覆盖重点为业务路径和真实边界，不以无关代码行数凑覆盖率。

补测试流程见 [newsclaw-test](../../.agents/skills/newsclaw-test/SKILL.md)。
