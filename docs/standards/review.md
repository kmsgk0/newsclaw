# 评审与完成定义

变更完成时，相关需求已有对应产物，必要检查通过，文档与任务状态反映实际结果。未实现或未验证的内容保持未完成。开发方法沿用[开发指南](../../CONTRIBUTING.md)。

## 检查表

按本次改动核对适用项：

| 检查项 | 看什么 |
| --- | --- |
| 需求与范围 | 实际改动有规约依据，需求得到落实，既定功能保留 |
| 正常与失败路径 | 正常操作得到预期结果，非法输入、资源缺失和依赖失败有明确反馈 |
| 权限与数据 | 私人数据不越权，写入、重复执行及删除符合业务约定 |
| AI 与来源 | 回答和生成结果有材料依据，提示词变更可追溯，相关样例已检查 |
| 测试与文档 | 已运行适用检查，入口、说明和完成状态与实际一致 |

检查结果随交付说明，发现问题时指出具体位置、现象和待处理内容。变更围绕明确目标组织，无关修改分开处理；必要例外在相关规约或规范中说明适用范围和理由。

## 检查方式

运行已有的 `npm run check -- --base main`，命令及覆盖范围见[仓库检查](../checks.md)。文档改动核对内容和链接，代码改动按[测试规范](testing.md)验证受影响行为，模型相关改动参考 [AI 评测样例](../evaluation/ai-cases.md)。

检查失败先定位并修正。所需功能或环境尚未具备时说明具体未执行项，不记为通过。
