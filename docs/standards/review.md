# 评审与完成定义

变更完成时，相关需求已有对应产物，必要检查通过，文档与任务状态反映实际结果。未实现或未验证的内容保持未完成。开发方法沿用[开发指南](../../CONTRIBUTING.md)。

## 检查表

按本次改动核对适用项：

| 检查项 | 看什么 |
| --- | --- |
| 需求与范围 | 实际改动有规约依据，需求得到落实，既定功能保留 |
| 正常与失败路径 | 正常操作得到预期结果，非法输入、资源缺失和依赖失败有明确反馈 |
| 权限与数据 | 私人数据不越权，写入、重复执行及删除符合业务约定 |
| AI 与来源 | 回答和生成结果有材料依据，提示词变更可追溯，相关样例已检查 |
| 测试与文档 | 已运行适用检查，入口、说明和完成状态与实际一致 |

检查结果随交付说明，发现问题时指出具体位置、现象和待处理内容。变更围绕明确目标组织，无关修改分开处理；必要例外在相关规约或规范中说明适用范围和理由。

## 检查方式

### 七类核查

| 对象 | 核查内容 | 手段与证据 |
| --- | --- | --- |
| 接口入口 | 参数、身份、对象归属和返回字段 | 对照 OpenAPI 与路由，脚本重放合法及非法请求，核对响应和写入 |
| 业务逻辑 | 需求覆盖、状态流转及业务结果 | AI 逐段阅读关联 Scenario 与实现，行为用例检查结果，需求歧义由人工确认 |
| 数据库操作 | 唯一约束、事务、查询与写入条件 | 阅读迁移和数据访问代码，用重复、并发和故障用例核对数据库变化 |
| 公共函数 | 重复逻辑、调用关系和异常传播 | AI 检索调用点及相似代码，复用已有测试验证共享行为 |
| 错误处理 | 非法输入、缺失对象和依赖失败的出口 | 用替身或故障输入触发路径，检查错误、非零退出及原有成功内容 |
| 安全与隐私 | 越权、输入处理、输出渲染和敏感信息 | 运行安全检查与[业务检查方法](../verification/security.md)，核对实际数据及脱敏输出 |
| 性能 | 循环查询、索引、分页及耗时边界 | AI 阅读查询与调用位置，具备运行条件后用相同输入测量并保留结果 |

检查者先说明代码要保证的行为，再核对实现依靠的机制及可能失效的条件。权限、并发、事务和数据一致性必须有对应规约、操作与数据证据；具体方法见[重点复核](../verification/security.md#权限并发与事务的重点复核)。

### 评审表与结论

每个实际检查的文件给出结论；同一组职责相同的文件可以共用一行，但须列明路径。评审表至少包含对象、需求依据、检查手段、判据、实际发现、结论及后续处理，并按以下维度核对适用内容。

| 维度 | 判定依据 |
| --- | --- |
| 需求覆盖 | 相关 Scenario 已实现、部分实现或未实现，状态与产物一致 |
| 需求一致性 | 数据含义、状态流转、权限与产品设计相符 |
| 失败路径 | 非法输入、依赖失败和提交失败有明确结果及验证 |
| 查询性能 | 循环查询、索引和分页问题有具体位置及运行依据 |
| 重复逻辑 | 重复代码的职责已核对，适合共享的行为有统一实现 |
| 漏洞风险 | 权限、输入、敏感内容与依赖检查有实际结果 |
| 高风险场景 | 权限、并发、事务与数据一致性有专门检查依据 |

结论使用“可用”“待修改”“风险无效”。可用表示本次检查范围符合依据；待修改列出位置、现象和修正要求；风险无效说明不可接受的行为及处理范围。未适用项写清原因，未执行的运行行为保持待验证。

记录注明执行者和方式，分别标识 AI 阅读、脚本结果及协作者独立复测。AI 检查发现的问题先核对原件和运行事实；修正后沿同一判据复测，并把可复用的检查加入对应测试或规则。文件检查表按本次检查范围维护，按检查项整理的安全评审见[安全检查评审记录](../../reports/review-01.md)。正文保留判断所需的关键输出，相关报告通过[报告索引](../../reports/README.md)查阅。

### 执行入口

运行已有的 `npm run check -- --base main`，命令及覆盖范围见[仓库检查](../verification/checks.md)。文档改动核对内容和链接，代码改动按[测试规范](testing.md)验证受影响行为，模型相关改动参考 [AI 评测样例](../verification/ai-cases.md)。

检查失败先定位并修正。所需功能或环境尚未具备时说明具体未执行项，不记为通过。
