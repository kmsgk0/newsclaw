# 数据库变更与发布状态

## 新闻关键词检索索引

[`018_news_text_search_indexes.sql`](../migrations/018_news_text_search_indexes.sql) 为 `news.content`、`news.summary` 和 `news.translation` 添加 trigram GIN 索引。**仅新增索引，处于扩展步骤，无迁移与收缩**。PostgreSQL 为已有记录建立索引，应用沿用同一检索 SQL 和数据格式。

索引在应用的迁移事务中创建，构建期间会阻塞对 `news` 的写入。发布前在同规模数据库副本测量建索引耗时，据此安排发布窗口。

隔离 PostgreSQL 上的迁移、关键词计数和分页执行计划见[性能报告](bench.md)。

## 会话与审计

会话与审计变更新增 `010_csrf_tokens.sql`、`011_request_audit.sql`、`012_skill_audit.sql` 和 `013_request_audit_filters.sql`。它们分别增加一次性令牌、HTTP 请求审计、技能调用审计及请求审计的筛选索引；本轮没有删除旧表或列。迁移与回归只在隔离数据库执行，尚未应用到真实部署。

按扩展、迁移、收缩三个阶段核对：

- **扩展**：新增表和索引并发布能读写它们的应用。技能审计与回答最终状态同事务提交；HTTP 请求审计为响应后写入。
- **迁移**：新请求产生新记录，历史请求和历史技能调用不会自动回填；一次性 token 属于新会话协议。现有持有刷新 Cookie 或使用浏览器来源的写入客户端需要先接入获取 token 的流程，应用与客户端应协调切换。
- **收缩**：本轮没有删除旧结构，也没有执行收缩阶段。回退前需确认应用版本和数据库备份兼容，不能假定迁移脚本提供自动回滚。

实际发布前应备份并在同规模副本测量迁移耗时，确认数据库权限、连接容量与停机窗口。应用首次运行时迁移以事务和数据库锁串行执行。
