# Proposal

## Why

为 NewsClaw 建立可启动的 API、账号和后台任务基础，使后续业务能够共用身份校验、数据存储、任务接收与错误响应。

## What Changes

- 实现注册、账号与唯一编辑记录初始化、登录、会话刷新、退出和密码更新接口。
- 实现配置校验、API 与 Worker 启停、健康检查、任务接收、outbox、有限重试、死信及任务权限。
- 准备共享数据模型和按序迁移，账号、任务及后续业务使用统一的账号和新闻标识。
- 建立容器、依赖、检查、备份恢复和开发文档入口，按职责组织已实现源码、测试与脚本。
- 完成账号与运行接口的正常、失败、并发、事务和权限检查，明确正式报告及本地原始输出的保存规则。

## Capabilities

### New Capabilities

- `account-access`: 账号初始化、会话、受保护接口与账号及任务归属。
- `runtime-operations`: 配置、API 与 Worker、后台任务、统一错误、日志及备份恢复。

### Modified Capabilities

- `contribution-workflow`: 文档与规约入口、增量交付及归档方式、API 检查命令。
- `engineering-standards`: 检查与报告保存规则，以及源码、测试、脚本和文档的职责划分。

## Impact

修改依赖和锁文件、共享迁移、服务入口、账号模块、任务运行模块、容器与 CI 配置、检查和备份恢复脚本及对应文档。业务模块在这些基础接口上接入；已准备的数据表保持为空，直到相应业务写入。
