# Design

## Context

模型适配器在结果校验成功后才返回用量，校验失败时调用方无法取得已经返回的用量。OpenAPI 转换直接读取 `schema.response`，未声明 schema 的路由导致文档生成异常。个人日报要求说明新闻与兴趣的关系，但没有清楚限定事实依据与推断边界。

## Decisions

### 失败调用记录

在已读取模型响应后保留用量，并沿错误对象传递给编辑失败出口。消息和调用日志保存同一份实际用量，回答继续标记为 failed，不把无效内容保存为成功结果。上游没有提供用量时沿用不可得状态，不推算数值。复用现有结构化结果与编辑场景检查，覆盖正常、结构无效及用量不可得的行为。

### 接口文档

在共享 Swagger 转换中处理合法缺省的路由 schema，保留已有请求与响应定义以及公开、受保护接口的区别。接口测试验证完整应用的 OpenAPI JSON、代表性业务路径和文档页面；浏览器检查页面实际加载接口定义。

### 个人日报

保留兴趣选材和个性化导读，明确事实只来自本批材料，兴趣关系作为分析表达，未披露事项直接说明缺口。具体产品计划、技术变动和因果判断须有材料依据。模型正文只整理报道事实；兴趣关联单独返回偏好片段、材料编号和原文片段，宿主核对其确实出自本次偏好与已选材料后生成说明。未找到直接关联时允许省略，不强行推断。无效关联使本次生成失败并保留已有日报。使用原问题材料及有、无兴趣的代表性样例固定输入与判据，分别检查事实、来源和个性化表达。自动用例检查调用与保存合同；真实模型输出按材料逐项核对，记录原始输出及判断。

### 记录与文档

`reports/security-fix-log.md` 保存三项问题的修复前后结果、检查入口及版本关联，`reports/review-02.md` 保存实际独立审查。首次检查记录保留原版本的结果，当前入口链接后续处理。完整日志、截图和模型输出留在 `.local/verification/`。

## Verification

先用现有 SEC-07 入口及新增接口文档用例复现原始失败，再验证修复后的结果与相邻行为。个人日报对照固定材料与实际生成结果。完整 Docker 验收覆盖仓库、安全、业务、接口、构建、浏览器及用量检查；独立审查核对实现与公开文字，完成后同步主规格和归档。
