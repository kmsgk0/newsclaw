# Design

## Context

个人编辑已有材料检索、会话和生成接口。阅读技能在同一套执行服务中提供明确的处理说明与输出形式，副本及执行结果按账号隔离。

## Goals / Non-Goals

**Goals:** 技能用途清楚、个人副本独立、显式选择生效，输出保留实际材料与来源。

**Non-Goals:** 不引入任意代码插件或通用智能体编排。

## Decisions

### 技能表达与副本

技能采用说明文本和配置。五项内置模板包含用途、输入范围、处理说明、输出形式及有代表性的示例。模板初始化仅更新系统模板，重复安装返回已有个人副本，公共模板变化不覆盖个人修改。修改、启用与停用均检查本人归属。

### 执行与结果

显式选择优先，服务端核对副本归属及启用状态。没有显式选择时，最多使用一项合适的已启用个人技能，也可普通回答。响应返回实际技能名称，失败沿用原材料及问题重试。

输出只依据新闻、事件或本人收藏中的实际材料。多源对比保留来源差异，简报使用有依据的进展，导图返回带来源的树形结构，双语阅读按段落编号对照实际原文。缺失、越权材料及无效结构明确失败，只有摘要时说明范围。

### 公开发布

发布接口只接收说明、输出形式及公开示例，保存草稿、已发布和已下架状态。作者与管理员按权限下架，公开版本不携带私人会话、记忆或阅读材料，已安装副本继续保留。

### 检查与调用观察

隔离测试核对模板、副本、选择、发布和五项输出结构，接口及模块文档说明实际调用方式。使用既有数据库和 HTTP 模型替身，对照双语结果正常返回与段落编号不合法两种情况，两种响应均提供固定用量。

观察入口 `tests/evaluation/usage-recording.ts` 比较回答状态、模型返回、调用日志和消息记录，输出预期、实际及判定。全部符合预期退出0，任一不符退出1；完整结果写入 `.local/verification/`，允许通过 `EVALUATION_DIR` 另存一次运行。观察本身保留发现的问题及其位置，正式检查记录依据实际结果填写。

## Risks / Trade-offs

结构合法只说明输出满足格式与来源范围，技能内容效果仍需对照真实材料检查。失败状态、原问题及已有成功回答继续保留。

## Migration Plan

使用共享迁移已准备的技能模板及副本表，初始化模板后验证重复安装与个人修改隔离。在隔离环境检查安装、编辑、启停、执行、发布及跨账号行为。
