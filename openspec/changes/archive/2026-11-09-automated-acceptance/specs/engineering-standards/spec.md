## ADDED Requirements

### Requirement: STD-09 自动验收报告

仓库 SHALL 为每轮验收生成 HTML 与 JSON 报告，包含版本及工作区状态、时间、阶段命令与结果、用例名称和需求编号、耗时及实际附件。报告只消费本轮检查结果，完整运行材料保存在 Git 忽略的独立目录，正式审查记录保持其真实状态。

#### Scenario: 阅读业务检查

- **GIVEN** 本轮测试已有实际结果
- **WHEN** 打开 HTML 报告
- **THEN** 能查看总体结论、失败原因及按账号、新闻、编辑、技能、专题、运行和工程检查组织的用例，需求编号及视口执行可以追溯到原用例，界面适应宽窄屏幕

#### Scenario: 检查结果不完整

- **GIVEN** 某阶段失败、被中断或没有产生必要结果
- **WHEN** 汇总报告
- **THEN** 如实区分失败、跳过和未执行，不从旧文件补结果或将缺失记录作为通过，错误文字安全显示

#### Scenario: 连续运行与附件

- **GIVEN** 已有历史运行材料
- **WHEN** 再运行一次验收
- **THEN** 本轮 HTML、JSON、日志、异步数据、截图和浏览器报告写入新的忽略目录，只链接本轮存在的附件，已有材料不被覆盖且生成物不进入 Git

#### Scenario: 调用用量检查失败

- **GIVEN** SEC-07 对照检查已取得正常与结构失败的实际结果
- **WHEN** 其中一个场景未保留模型已返回的用量
- **THEN** 总体结论为失败，报告显示 SEC-07 用例及预期和实际差异，并提供本轮用量记录附件；已知问题不转为跳过或预期通过

#### Scenario: 已登记的审查问题

- **GIVEN** 正式审查记录包含自动套件之外的已知问题
- **WHEN** 本轮自动测试通过
- **THEN** 结论明确针对已执行检查，提供既有审查记录入口，保留问题的原判定
