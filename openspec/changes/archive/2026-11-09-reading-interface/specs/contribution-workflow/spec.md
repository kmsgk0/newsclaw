## MODIFIED Requirements

### Requirement: FLOW-06 本地与 PR 使用一致的检查入口

仓库 MUST 提供 npm 检查命令，并在面向 `main` 的 PR 创建、更新提交和重新打开时执行 GitHub Actions 检查。仓库检查与安全检查分别显示结果，使用相同的本地实现；命令失败返回非零并说明对象及原因，`npm run check` 中的仓库与安全检查无需业务服务或模型调用。`make check` 依次调用该仓库检查以及应用的静态、类型、行为、接口、构建和浏览器检查，各阶段只执行一次。应用检查使用隔离数据库、队列和外部服务替身，任一阶段失败立即停止。

#### Scenario: 检查仓库变更

- **GIVEN** 仓库依赖和检查工具已准备好
- **WHEN** 在本地执行统一入口，或 PR 触发 workflow
- **THEN** 执行规定的规格、文件、提交和安全检查，输出各项结果，失败检查不能报告成功

#### Scenario: 检查 PR 的合并结果

- **GIVEN** 一个可以合并到 `main` 的 PR
- **WHEN** workflow 运行
- **THEN** 在合并结果上检查文件和规格，提交引用检查仅覆盖该 PR 的开发者提交，平台生成的合并提交不参与提交格式检查

#### Scenario: 完整应用检查

- **GIVEN** 仓库检查工具及隔离应用测试环境已准备好
- **WHEN** 执行 `make check`
- **THEN** 仓库检查和各应用单项 npm 命令按顺序执行一次，任一失败返回非零且后续阶段不再执行
