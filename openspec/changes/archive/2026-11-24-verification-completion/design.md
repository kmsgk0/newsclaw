# Design

## Context

编辑页使用 URL 选择会话和材料，聊天组件维护草稿与流式状态。接口通过共享入口生成 OpenAPI，并在发送时统一封装 JSON；文档声明须保留原有响应内容。测试已具备隔离数据库、真实 Worker、模型 HTTP 替身及三种视口。

## Goals / Non-Goals

完成选材后的稳定输入、准确且可试调的接口文档，以及可复现的检查和使用记录。产品权限、响应字段和既有业务语义沿现行合同。

## Decisions

- 以一次材料选择对应的会话状态更新为边界，避免独立的重挂载和延后路由更新再次清空新输入。浏览器检查沿用户选材、输入、发送、回看路径验证。
- 停止和发送使用独立的按钮节点。停止后的可见状态保留重试入口，刷新后按已保存的状态恢复。
- 从本人阅读记录返回 `readAt` 并在最近阅读列表显示。分享预览读取所选成果的 `createdAt`，发布时将该时间写入快照。注册按钮表述创建账号，生成用量说明包含失败重试。
- 通过文档生成层读取路由的成功响应元数据，统一生成信封与错误声明。元数据不参与运行时序列化，保护原有业务返回字段。异步接收共享任务结构，SSE 单独声明内容类型及事件。
- Swagger 使用浏览器请求拦截器为已认证写请求取得一次性 CSRF token；认证和权限继续由现有服务验证。
- 复用现有 Compose、API、Worker 与测试替身，整理本地启动和手机任务验证脚本。脚本使用独立账号与数据，输出关键状态及审计结果，原始输出进入被忽略的验证目录。自动验证先检查工作区状态，只在实际开始启动后清理本次 Compose 环境。
- 场景对应表逐项读取现有断言和检查记录，业务场景对应行为用例，工程场景对应工具、配置或审查。三个读者分别操作产品，反馈与处理结果及已验证的修复提交关联。

## Risks / Trade-offs

- 路由过渡和界面输入时序通过浏览器回归验证，既有会话恢复与新建行为一并核对。
- 自动化环境使用固定替身取得可重复结果，内容质量检查使用实际新闻和模型服务，并记录各自执行条件。
