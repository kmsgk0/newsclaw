# Contribution Workflow Specification

## MODIFIED Requirements

### Requirement: FLOW-01 开发前准备规约与文档依据

所有仓库修改 MUST 纳入 OpenSpec，包括业务代码、页面、工具、依赖、配置、CI、文档和工程规范。开发者能够从 README 找到产品规划、现行规格、活动变更及工程规范。产品规划保存完整目标、设计与后续安排，活动变更限定本轮交付内容；实施前准备覆盖该范围的提案、设计、需求场景和任务，沿用已有需求编号，内容详略与实际影响相称。已有活动变更覆盖本次内容时沿用，需要变化时更新。

#### Scenario: 从仓库进入开发

- **GIVEN** 开发者已取得 NewsClaw 仓库
- **WHEN** 从 README 阅读本次工作相关的文档
- **THEN** 能找到需求与实施状态、适用工程规范和开发方法，相关本地链接均指向仓库内有效文件

#### Scenario: 新增检查工具

- **GIVEN** 计划新增检查工具，已有规约未覆盖其行为
- **WHEN** 准备实现该工具
- **THEN** 先完成对应变更的提案、设计、输入与结果场景、失败场景和实施任务，再开始实现

#### Scenario: 修正文档

- **GIVEN** 计划修正文档中的错误说明
- **WHEN** 准备对应规约
- **THEN** 写清修正内容及核对方法；仍覆盖本次内容的活动变更可以沿用

#### Scenario: 查阅完整产品规划

- **GIVEN** 产品包含已确定但尚未实现的能力
- **WHEN** 开发者从产品入口查看需求、设计和路线图
- **THEN** 能找到全部目标及其场景、验证要求和实施安排，未实现能力保持计划状态

#### Scenario: 组织一次增量变更

- **GIVEN** 产品规划中已有完整需求与后续任务
- **WHEN** 准备实施一个明确的交付范围
- **THEN** 当前变更只包含该范围的实现、测试和文档任务，其余需求与验证要求继续保留在产品规划中

#### Scenario: 调整产品文档位置

- **GIVEN** 需求、设计和实施安排需要调整目录
- **WHEN** 完成文档迁移与入口更新
- **THEN** 需求编号、场景内容、设计依据及验证要求完整保留，相关链接有效，任务状态不因迁移改变

### Requirement: FLOW-05 完成后同步规格与归档

任务 MUST 在对应实现及规定验证完成后勾选。变更的全部任务完成后同步主规格并归档，随后核对主规格内容并运行严格校验。归档只同步本轮已实现并验证的范围。路线图关联相应变更，完成状态在该变更中维护；已交付的需求正文由现行规格维护，产品入口保留编号、摘要和链接，剩余目标继续留在规划中。继续实施的变更仍有未完成内容时保持活动状态。规划已由产品文档完整承接、后续工作转由增量变更管理时，原规划变更可保留任务状态归档，跳过未实现规格的同步。

#### Scenario: 变更完成

- **GIVEN** 变更的实现及规定验证均已完成，任务清单与实际结果一致
- **WHEN** 整理变更
- **THEN** 将已实现并验证的规格同步到主规格，保存归档材料，主规格及变更通过严格校验

#### Scenario: 仍有未完成内容

- **GIVEN** 变更仍在实施且仅完成部分实现或验证
- **WHEN** 更新项目文档与任务状态
- **THEN** 已完成任务与剩余任务清楚区分，变更保持活动状态，项目介绍不将剩余目标写成已实现功能

#### Scenario: 产品仍有后续能力

- **GIVEN** 当前变更已完成实现与验证，产品规划中还有未纳入本轮的能力
- **WHEN** 同步并归档当前变更
- **THEN** 已完成范围进入现行规格，产品入口与路线图提供相应链接，其他能力继续保留为后续计划

#### Scenario: 归档已由产品文档承接的规划

- **GIVEN** 原规划的需求、设计与未完成任务已完整迁入产品文档，后续工作由独立增量变更管理
- **WHEN** 归档原规划变更
- **THEN** 保留原始材料与任务状态，修正归档后的链接，跳过未实现规格的同步，完整需求和后续安排仍可从产品入口查阅
