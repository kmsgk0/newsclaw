# Design

## Context

新闻和编辑接口已经提供报道、引用及生成结果。专题负责保存本人材料与成果，关注连接后续新闻，结构化洞察和公开快照通过 API 提供。

## Goals / Non-Goals

**Goals:** 私人资料可维护，来源快照可追溯，持续更新与公开分享有明确状态和权限。

**Non-Goals:** 不建设独立图数据库或额外任务平台。

## Decisions

### 专题与成果

专题条件使用统一新闻领域及关键词规则。自动匹配与手动加入共用报道关联，手动移除保存为排除关系，刷新时遵守排除，主动重新加入删除对应排除。笔记记录修改时间，提供读取、修改及删除接口。

成果保存使用已完成消息、生成正文、技能和来源快照，提供改名和删除接口。删除成果时撤销关联分享，公共新闻及其他成果保留。新闻接口可以将报道加入本人专题，编辑和技能材料服务复用相同专题归属校验。

### 关注、提醒与日期

关注列表返回 kind、id、title、url 及创建时间，提醒保留命中原因及阅读地址。同一账号与报道只产生一条提醒，多个关注原因保存在同一条记录中；执行时再次核对关注是否有效，失败恢复不丢失待处理消息。本人可以读取未读数、标记单条及全部已读。

业务日期采用 Asia/Shanghai，SQL 日期直接返回日期字符串。热点排名窗口与 historyDays 分开，历史趋势依据对应业务日的实际统计。事件报道按发布时间和稳定标识排列。

### 结构化洞察与分享

导图保存树形结构及节点来源，实体关系保存实际报道依据。新闻归属或有效提取结果改变时，图谱查询使用当前关联。API 返回节点、边及来源，客户端可以按同一组数据提供图形或列表。

分享保存发布时的独立快照，仅含本人确认的成果标题、正文及公共来源。读取待公开内容与发布使用同一字段范围，撤销使公开访问失效，私人原件仍保留。所有私人操作检查所属账号。

### 模块与验证

专题、成果、关注和分享按业务职责维护，提醒处理器复用已有任务运行模块。隔离测试核对自动匹配、排除与恢复、笔记和成果、日期、来源、取消关注、重复消息、快照及跨账号访问。接口与模块文档说明可用请求及结果结构。

## Risks / Trade-offs

模型结构与来源通过校验后才可保存为有效成果。提醒在提交前核对当前关注，旧任务或已取消关注不能产生新的私人消息。

## Migration Plan

使用共享迁移已准备的数据表与索引，保留新闻及私人对象标识。接入专题材料、关系持久化和提醒处理后，核对既有新闻、收藏、会话与技能结果，完成相邻接口回归。
