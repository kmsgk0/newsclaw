# Design

## Context

沿用现有编辑服务、任务轮询、参数化数据访问及隔离测试环境。缺陷触发条件见 proposal 和对应 delta 场景。

## Goals / Non-Goals

保持现有接口、权限、来源校验和页面效果；每项改动可独立审阅及回退。本轮只处理已审查的四项缺陷和四项重构，不新增订阅、导出或额度功能。

## Decisions

- 普通回答按模型轮次收集文本，只有不再请求工具的终轮进入正文。保留宿主的摘要范围提示。工具状态继续使用独立 SSE 事件。
- 任务终态向父层传递实际任务，避免父子两份状态不一致；分区切换使用明确组件身份隔离状态。
- 模型适配器在所有流式失败出口携带当前用量；统一用量合并，未知字段传播 null，区分尚未发生调用和已发生但未知的调用。
- 专题部分更新采用单条带归属条件的 UPDATE，只更新提交字段，避免在应用层读旧值再写回。匹配刷新与更新放在同一事务内。
- 聊天 Hook 管理发送、取消、恢复及会话状态；独立函数消费 SSE；消息列表负责展示。滚动与材料选择保持在界面层。
- 日报和手记复用已有按标识批量读取新闻的方法；保留输入顺序及缺失新闻的既定处理。
- 专题详情以一次带账号条件的专题读取作为存在性判断，各子查询直接带账号条件，避免重复读取专题。
- 独立审计模块集中 schema、路由和数据访问；基础应用只装配模块。保留管理员限制、筛选与脱敏字段。

## Risks / Trade-offs

- 聊天拆分可能影响取消、重试和滚动 → 复用既有浏览器回归，增加终态和多轮缺陷场景。
- 查询合并可能弱化归属检查 → 子查询保留所有者约束，实际检查跨账号拒绝及不改变数据。
- 用量可能不完整 → 返回已提供字段，未知项保留 null，不假定总量可推算。

## Migration Plan

无数据迁移和新增依赖。逐项通过针对性测试后提交；最后完整检查、构建、浏览器验收，同步主规格并归档。每个实现提交关联本变更及任务编号。
