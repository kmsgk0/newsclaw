# 安全检查方法与评审记录

## Why

NewsClaw 已有工程规范和仓库检查工具，需要把安全要求落实为明确的检查对象、操作与判据，并为实际检查保留可查阅的结果。统一检查方法、评审口径和报告入口，使开发者能够验证产品边界并复测发现的问题。

## What Changes

- 编写七项安全检查及权限、并发、事务的检查方法，准备问答检查样例，保留公共新闻访问与个人配置的既有权限。
- 补充七类代码核查、七个评审维度和结论要求，明确检查来源、未执行状态及复测方式。
- 使用现有 npm 检查命令和 PR workflow，核对文档引用、实际执行与结果记录一致。
- 建立报告索引、安全基线及文档与工具审查记录，详细证据按日期和主题归组。
- 同步产品路线图、运行日志目标与文档入口，业务检查继续随对应实现执行。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `engineering-standards`：补全具体安全检查方法、评审依据及报告组织要求。

## Impact

新增 `docs/security-checks.md` 及 `reports/` 中的报告与证据；更新评审、安全、测试、运维规范、运行目标需求、总体设计与路线图中的命令引用、README、AGENTS 和检查说明。检查工具和依赖沿用现有实现，必要修正以实际检查发现为依据。

本变更交付检查方案、命令入口及当前文档和工具的实际记录。业务接口、运行日志和异步行为的实测任务保持未完成；本次不新增应用实现或部署环境。
