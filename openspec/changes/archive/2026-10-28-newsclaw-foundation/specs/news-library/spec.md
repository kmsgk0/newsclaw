# news-library specification

## Purpose

提供全站共享且可以追溯来源的新闻库，统一承接多来源采集、筛选、摘要、翻译、事件聚合和检索，为新闻阅读、个人编辑、日报、专题及可视化提供同一份可靠的内容入口。

## ADDED Requirements

### Requirement: NEWS-01 信源管理与保留来源的采集

系统 SHALL 支持管理员配置 RSS、公开 API 和可正常访问的新闻网页信源，采集标题、来源、发布时间、规范化原文链接及实际取得的正文。新闻按信源与规范化原文链接识别；重复采集更新已有报道，跨来源相同正文保留各自报道记录，可复用正文和处理结果。

#### Scenario: 采集不同类型信源
- **GIVEN** 管理员已启用可访问的 RSS、公开 API 或网页信源。
- **WHEN** 对应采集任务执行成功。
- **THEN** 新闻库保存取得的报道及完整来源信息，新闻详情提供原文链接和实际可用的正文或摘要。

#### Scenario: 重复采集与跨来源转载
- **GIVEN** 信源 A 的报道已入库，信源 B 另有正文相同、原文链接不同的报道。
- **WHEN** 系统再次采集 A 的报道并首次采集 B 的报道。
- **THEN** A 不增加重复记录，B 的来源、链接和发布时间独立保留，两篇报道都能被打开。

#### Scenario: 无效信源参数与越权管理
- **GIVEN** 请求缺少信源类型或有效地址，或者调用者没有管理员权限。
- **WHEN** 调用者新增或修改信源。
- **THEN** 系统分别返回参数错误或无权限，不保存无效信源，也不发起采集请求。

#### Scenario: 信源不可达
- **GIVEN** 已配置的信源连接失败或返回无法解析的内容。
- **WHEN** 采集任务执行。
- **THEN** 任务记录明确失败原因，已有新闻仍可查看，不用模型编造报道或把失败记成无新闻成功。

### Requirement: NEWS-02 筛选、摘要与翻译

系统 SHALL 清洗采集文本并通过模型筛选资讯、生成摘要，为外文内容提供中文翻译与原文对照。来源原文和模型生成结果分别标识；来源只有摘要时必须标明材料范围。成功结果供全站复用，处理失败时保留原文与已有成功结果。

#### Scenario: 生成摘要与中文译文
- **GIVEN** 一篇外文新闻已取得正文且尚未完成处理。
- **WHEN** 清洗、筛选、摘要与翻译任务成功。
- **THEN** 新闻保存筛选结果、摘要和对应译文，页面可以查看原文及译文，并标识生成内容。

#### Scenario: 来源仅提供摘要
- **GIVEN** 信源仅返回标题、摘要与原文链接。
- **WHEN** 新闻详情展示内容或编辑读取材料。
- **THEN** 系统明确内容只有摘要，保留原文入口，不把生成的扩写当作新闻原文。

#### Scenario: 模型失败后补做缺失结果
- **GIVEN** 新闻已保存正文和摘要，但翻译调用失败。
- **WHEN** 用户查看新闻，随后管理员重新执行未完成处理。
- **THEN** 页面保留正文和摘要并说明译文暂不可用；重试仅补缺失结果，不丢弃已有内容或重复创建新闻。

### Requirement: NEWS-03 事件归并与管理修正

系统 SHALL 将围绕同一事件的报道关联到共同事件，展示事件概况、多来源报道和后续进展。聚合参考标题、时间、实体和内容；无法判断时允许报道独立展示。管理员可修正错误归属，相关问答、时间线与图谱使用修正后的关系。

#### Scenario: 多来源报道汇入同一事件
- **GIVEN** 新闻库包含同一事件的多篇独立报道。
- **WHEN** 系统确认其事件归属。
- **THEN** 事件详情汇集这些报道，保留各自来源和发布时间，新报道追加到事件中而不覆盖旧报道。

#### Scenario: 管理员修正归属
- **GIVEN** 管理员已登录，一篇报道被关联到错误事件。
- **WHEN** 管理员将其移动到正确事件或解除关联。
- **THEN** 事件关联更新，报道原文与来源记录保留，时间线和关系查询不继续使用旧归属。

#### Scenario: 请求不存在的事件
- **GIVEN** 目标事件标识不存在。
- **WHEN** 访客访问其详情或编辑请求该事件。
- **THEN** 系统返回资源不存在，不生成无来源的事件概况。

### Requirement: NEWS-04 资讯浏览与关键词、向量检索

系统 SHALL 在资讯中心展示当日精选，并支持按关键词、领域和来源筛选；新闻库建立关键词及向量索引，供精确查找和按含义检索使用。结果必须关联到新闻及来源，默认每页 20 条、最多 100 条，排序使用唯一标识兜底。

#### Scenario: 浏览并检索报道
- **GIVEN** 新闻库存在可见报道，其关键词和向量索引已完成。
- **WHEN** 用户浏览精选、输入关键词，或编辑执行语义检索。
- **THEN** 系统返回范围内匹配的新闻及来源，用户能打开对应详情；连续分页在数据不变时不重复或遗漏同一结果。

#### Scenario: 合法查询没有结果
- **GIVEN** 检索参数有效，但新闻库没有匹配报道。
- **WHEN** 用户提交查询。
- **THEN** 系统返回空结果，页面说明没有匹配内容并允许调整条件，不展示编造的报道。

#### Scenario: 非法筛选被明确拒绝
- **GIVEN** 请求含不支持的筛选字段、错误类型或越界页大小。
- **WHEN** 请求新闻列表或检索结果。
- **THEN** 系统返回参数错误，不按缺省条件返回全量新闻。

#### Scenario: 检索依赖失败
- **GIVEN** 查询需要的数据库、索引或嵌入服务不可用。
- **WHEN** 系统执行查询。
- **THEN** 系统明确返回依赖不可用，不把故障伪装为空结果；已打开的新闻内容仍保持可读。

### Requirement: NEWS-05 收藏与阅读记录

系统 SHALL 为登录用户保存自己的收藏及阅读记录，支持取消收藏、浏览收藏和再次打开读过的新闻。收藏按用户与新闻保持唯一；阅读记录记录最近阅读时间，私人列表遵守账号归属。

#### Scenario: 收藏并回看新闻
- **GIVEN** 用户已登录，新闻存在。
- **WHEN** 用户打开新闻、连续收藏两次，再查看收藏和阅读记录。
- **THEN** 系统保留一份收藏和该新闻的最近阅读记录，均能回到对应新闻；取消收藏后只移除收藏，不删除新闻。

#### Scenario: 收藏不存在或无权访问的对象
- **GIVEN** 新闻标识不存在，或用户请求的是其他账号的收藏记录。
- **WHEN** 用户提交收藏或读取请求。
- **THEN** 系统返回资源不存在，不产生悬空收藏，也不泄露其他账号记录。

### Requirement: NEWS-06 全站日报

系统 SHALL 按日期把公共新闻库中的当日重要内容整理为全站日报，保留生成时间、覆盖范围、新闻条目和来源链接，允许游客浏览历史日报。重复触发同一日期的生成不得增加重复日报；失败不得覆盖上一份成功结果。

#### Scenario: 生成并回看全站日报
- **GIVEN** 当日新闻已完成必要整理。
- **WHEN** 日报任务成功并被重复触发。
- **THEN** 该日期保持一份全站日报，重要条目都能打开来源，历史日期的日报仍可按日期查看。

#### Scenario: 无内容与生成失败有不同结果
- **GIVEN** 某日没有可用新闻，或者模型在生成过程中失败。
- **WHEN** 系统处理全站日报任务。
- **THEN** 无新闻时明确说明暂无内容；模型失败时记录生成失败并保留已有成功日报，两种情况不得混为成功生成的空日报。
