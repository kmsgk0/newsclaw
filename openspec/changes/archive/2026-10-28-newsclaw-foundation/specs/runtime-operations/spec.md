# runtime-operations specification

## Purpose

规定 NewsClaw 可复现启动、后台任务、错误处理、运行记录和恢复的可观察行为，让新闻处理与个人内容生成在失败时保持明确状态，并使开发者能够依据同一组需求验证、部署和恢复系统。

## ADDED Requirements

### Requirement: OPS-01 配置、启动与健康检查

系统 SHALL 使用 Dockerfile、Compose、依赖锁文件和无密钥配置示例支持按文档从零启动应用及必要依赖。必需配置缺失必须启动失败。免认证的 `/health` 返回版本、时间和必要依赖连通状态，独立存活检查反映进程存活；模型连接诊断不得发送付费生成请求。

#### Scenario: 按文档启动
- **GIVEN** 使用者取得仓库、准备文档规定的环境并填入必要配置。
- **WHEN** 使用者执行文档中的一条启动命令。
- **THEN** 应用与依赖启动，数据卷持久化，匿名访问 `/health` 可取得版本、时间和依赖状态，无需额外口头步骤。

#### Scenario: 必需配置缺失
- **GIVEN** 一个必需配置项未填写或格式无效。
- **WHEN** 应用尝试启动。
- **THEN** 启动明确失败并指出配置项名称，不输出密钥值，不用隐式默认值继续运行。

#### Scenario: 数据库未就绪
- **GIVEN** 应用进程仍在运行，但数据库不可达。
- **WHEN** 运行环境查询存活与健康状态。
- **THEN** 存活检查仍反映进程状态，健康检查报告依赖未就绪并返回失败状态，不把故障伪装为健康。

### Requirement: OPS-02 后台任务状态与重复执行

系统 SHALL 统一管理采集整理、日报、编辑手记和更新提醒任务，记录待执行、执行中、成功、失败及失败原因。管理员可查看和重新执行公共失败任务。任务设置明确超时，进程中断后遗留的执行中任务可识别并重新领取；业务唯一键防止重复新闻、日报、手记和提醒。

#### Scenario: 任务成功及重复触发
- **GIVEN** 有待执行的合法任务，所需外部服务可用。
- **WHEN** 执行器领取任务并完成处理，随后相同业务任务再次触发。
- **THEN** 状态按待执行、执行中、成功变化，重复触发遵守各能力的唯一性规则，不产生重复业务结果。

#### Scenario: 外部调用失败
- **GIVEN** 执行中的任务遇到模型或信源故障。
- **WHEN** 执行器结束本次尝试。
- **THEN** 任务记录失败和具体原因，原有成功内容保留，管理员能区分未完成步骤并重新执行，不进行无上限自动重试。

#### Scenario: 执行器中断后的恢复
- **GIVEN** 某任务在执行中发生进程中断，并已超过记录的执行时限。
- **WHEN** 执行器恢复并检查未完成任务。
- **THEN** 系统识别该任务未完成，允许重新领取；重新执行沿业务唯一键写入，不重复处理已成功提交的结果。

#### Scenario: 越权或缺失任务操作
- **GIVEN** 普通用户尝试重新执行公共管理任务，或者管理员指定的任务不存在。
- **WHEN** 系统接收重试请求。
- **THEN** 系统分别返回无权限或资源不存在，不创建替代任务，不修改其他任务。

### Requirement: OPS-03 统一错误与事务边界

系统 SHALL 为 JSON 业务响应使用 `code`、`message`、`data`、`requestId`，成功业务码为 `OK`，失败使用登记的业务码及匹配的 HTTP 状态。流式接口通过事件提供同等错误信息。外部模型、网络及文件处理在数据库事务之外完成，成功结果使用短事务写入，失败不能提交不完整业务状态。

#### Scenario: 参数校验失败返回明确错误
- **GIVEN** 请求包含不支持的状态、非法筛选字段或类型错误的参数。
- **WHEN** 接口边界校验请求。
- **THEN** 系统返回登记的参数错误、可读信息及请求标识，不执行后续业务写入，也不退化为默认成功操作。

#### Scenario: 外部结果成功但提交失败
- **GIVEN** 某任务已取得外部结果，但数据库事务提交失败。
- **WHEN** 系统处理该结果。
- **THEN** 系统报告失败，不推进对应业务处理位置，不保留半份成果；原成功数据不被覆盖。

#### Scenario: 流式错误可关联请求
- **GIVEN** 一次编辑回答已经开始流式返回，随后依赖调用失败。
- **WHEN** 系统发送终止错误事件。
- **THEN** 事件包含与该请求一致的标识、业务错误与可读提示，前端标记未完成，后台能够定位对应失败。

### Requirement: OPS-04 运行记录与行为验证

系统 SHALL 使用单行 JSON 日志记录时间、级别、模块、请求或任务标识、结果及必要耗时，使请求和工具调用可以关联。日志不得包含密码、令牌或私人问答正文。测试按需求场景覆盖正常、失败和边界，使用独立数据与可控外部替身，提供一键运行命令及失败退出码。

#### Scenario: 查询一次请求及工具调用
- **GIVEN** 用户执行了一次包含 MCP 调用的编辑请求。
- **WHEN** 开发者按请求标识查询日志。
- **THEN** 能关联请求及工具调用的结果和必要耗时，日志每行可独立解析为 JSON，不包含敏感凭据和私人问答正文。

#### Scenario: 测试发现行为错误
- **GIVEN** 测试环境独立，模型、信源和时间均可控制，账号隔离或去重逻辑被改坏。
- **WHEN** 开发者按文档执行一键测试。
- **THEN** 对应行为测试失败，命令以非零退出码结束，报告指出需求场景，不能以跳过或模拟成功掩盖失败。

#### Scenario: 无外网运行行为测试
- **GIVEN** 测试数据和外部服务替身已准备完成。
- **WHEN** 在没有外网访问的环境运行测试。
- **THEN** 正常、失败及边界场景仍可验证，不依赖真实模型调用或产生模型费用；真实模型效果核验单独记录。

### Requirement: OPS-05 版本发布与数据恢复

系统 SHALL 按版本或提交标识构建及发布，顺序包含构建、迁移、启动、健康检查与行为验证。发布前保留上一可运行版本和数据库备份，迁移说明恢复方式。初始备份每日一次、保留最近 7 份，恢复目标为最多损失一天数据且两小时内恢复，实际能力以恢复演练记录核验。

#### Scenario: 发布成功与优雅停止
- **GIVEN** 新版本已完成必要验证，上一版本与数据库备份可用。
- **WHEN** 操作者按文档发布并停止旧进程。
- **THEN** 新版本显示对应版本标识并通过健康检查；旧进程停止接收新任务，完成或明确中断在途工作，未完成任务可按任务规则恢复。

#### Scenario: 发布失败后恢复
- **GIVEN** 新版本启动或验证失败，且迁移记录说明了回退对数据的影响。
- **WHEN** 操作者执行文档中的恢复步骤。
- **THEN** 系统恢复到匹配的可运行版本和数据状态，重新验证健康及主要行为，并记录实际恢复耗时和数据恢复点。

#### Scenario: 备份不可读取
- **GIVEN** 选定备份缺失或无法读取。
- **WHEN** 操作者执行恢复检查。
- **THEN** 恢复明确失败，不删除当前数据，不把未经验证的备份记为可恢复，报告可查明的失败原因。
