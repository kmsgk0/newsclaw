# Design

## Context

API 处理 HTTP 与编辑技能，队列保存在 Redis；Worker 与 API 分进程。技能按固定的五类统计，不以用户、技能副本、新闻或请求标识作为标签。API 从 BullMQ 读取共享队列状态。

## Decisions

使用进程内固定桶直方图记录 API 路由模板、方法和状态的响应耗时；仅记录五种固定技能类型的成功和失败次数。采集文本不包含 URL 参数、用户标识或正文。进程重启时内存计数重置，由采集端保存历史；多实例各自采集。

指标服务与 API 分端口，默认关闭并绑定回环地址；Compose 仅在启用时将服务绑定到容器网络，不映射指标端口至宿主。队列采集失败时报告不可用，不把失败显示为零积压。可选监控服务采用 Compose profile，Prometheus 定期采集，Grafana 使用预配置数据源及三类面板；管理口只绑定本机且密码由环境提供。

告警规则覆盖队列积压和技能执行错误。隔离验证须真实采集样本并观察告警状态，合成模型或信源只用于测试；规则测试和真实告警分别记录。

## Verification

测试指标标签、固定桶、结果区分、Redis 失败和非公开默认值；在隔离 Compose 验证采集、面板配置、真实告警与关闭清理。记录命令、版本、观察值和限制；未执行项不勾选。
