## MODIFIED Requirements

### Requirement: FLOW-06 本地与 PR 使用一致的检查入口

仓库 MUST 提供 npm 检查命令，并在面向 `main` 的 PR 创建、更新提交和重新打开时执行 GitHub Actions 检查。仓库检查与安全检查分别显示结果，使用相同的本地实现；命令失败返回非零并说明对象及原因，`npm run check` 中的仓库与安全检查无需业务服务或模型调用。`make check` 依次调用该仓库检查以及已实现 API 的静态、类型、行为、接口和构建检查，各阶段只执行一次。应用检查使用隔离数据库、队列和外部服务替身，任一阶段失败立即停止。

#### Scenario: 检查仓库变更

- **GIVEN** 仓库依赖和检查工具已准备好
- **WHEN** 在本地执行统一入口，或 PR 触发 workflow
- **THEN** 执行规定的规格、文件、提交和安全检查，输出各项结果，失败检查不能报告成功

#### Scenario: 检查 PR 的合并结果

- **GIVEN** 一个可以合并到 `main` 的 PR
- **WHEN** workflow 运行
- **THEN** 在合并结果上检查文件和规格，提交引用检查仅覆盖该 PR 的开发者提交，平台生成的合并提交不参与提交格式检查

#### Scenario: 完整应用检查

- **GIVEN** 仓库检查工具及隔离应用测试环境已准备好
- **WHEN** 执行 `make check`
- **THEN** 仓库检查和各应用单项 npm 命令按顺序执行一次，任一失败返回非零且后续阶段不再执行

### Requirement: FLOW-01 开发前准备规约与文档依据

所有仓库修改 MUST 纳入 OpenSpec，包括业务代码、页面、工具、依赖、配置、CI、文档和工程规范。开发者能够从 README 和文档导航找到产品范围、现行架构、能力规格、活动变更及工程规范。已交付行为由现行规格维护，活动变更保存未交付目标和本轮实施安排；实施前准备覆盖该范围的提案、设计、需求场景和任务，沿用已有需求编号，内容详略与实际影响相称。已有活动变更覆盖本次内容时沿用，需要变化时更新。

#### Scenario: 从仓库进入开发

- **GIVEN** 开发者已取得 NewsClaw 仓库
- **WHEN** 从 README 阅读本次工作相关的文档
- **THEN** 能找到需求与实施状态、适用工程规范和开发方法，相关本地链接均指向仓库内有效文件

#### Scenario: 新增检查工具

- **GIVEN** 计划新增检查工具，已有规约未覆盖其行为
- **WHEN** 准备实现该工具
- **THEN** 先完成对应变更的提案、设计、输入与结果场景、失败场景和实施任务，再开始实现

#### Scenario: 修正文档

- **GIVEN** 计划修正文档中的错误说明
- **WHEN** 准备对应规约
- **THEN** 写清修正内容及核对方法；仍覆盖本次内容的活动变更可以沿用

#### Scenario: 查阅完整产品规划

- **GIVEN** 产品包含已确定但尚未实现的能力
- **WHEN** 开发者从文档导航查看需求、架构和相关变更
- **THEN** 能找到全部目标及其场景、验证要求和实施安排，未实现能力保持计划状态

#### Scenario: 组织一次增量变更

- **GIVEN** 已有明确需求与后续目标
- **WHEN** 准备实施一个明确的交付范围
- **THEN** 当前变更只包含该范围的实现、测试和文档任务，其余已确认目标和验证要求仍可从文档入口找到，并保持真实状态

#### Scenario: 调整产品文档位置

- **GIVEN** 需求、设计和实施安排需要调整目录
- **WHEN** 完成文档迁移与入口更新
- **THEN** 需求编号、场景内容、设计依据及验证要求完整保留，相关链接有效，任务状态不因迁移改变

### Requirement: FLOW-05 完成后同步规格与归档

任务 MUST 在对应实现及规定验证完成后勾选。变更的全部任务完成后同步主规格并归档，随后核对主规格内容并运行严格校验。归档只同步本轮已实现并验证的范围。文档导航关联能力规格与相关变更，完成状态在变更任务中维护。已交付需求正文由现行规格维护，后续目标保存在对应变更中。继续实施的变更仍有未完成内容时保持活动状态。规划内容已由后续变更完整承接时，原规划变更可保留任务状态归档，跳过未实现规格的同步。

#### Scenario: 变更完成

- **GIVEN** 变更的实现及规定验证均已完成，任务清单与实际结果一致
- **WHEN** 整理变更
- **THEN** 将已实现并验证的规格同步到主规格，保存归档材料，主规格及变更通过严格校验

#### Scenario: 仍有未完成内容

- **GIVEN** 变更仍在实施且仅完成部分实现或验证
- **WHEN** 更新项目文档与任务状态
- **THEN** 已完成任务与剩余任务清楚区分，变更保持活动状态，项目介绍不将剩余目标写成已实现功能

#### Scenario: 产品仍有后续能力

- **GIVEN** 当前变更已完成实现与验证，已有未纳入本轮的后续能力
- **WHEN** 同步并归档当前变更
- **THEN** 已完成范围进入现行规格，文档导航提供相应链接，其他能力在对应变更中保持计划状态

#### Scenario: 归档已由产品文档承接的规划

- **GIVEN** 原规划的需求、设计与未完成任务已有完整保存，文档入口已关联承接这些内容的后续变更
- **WHEN** 归档原规划变更
- **THEN** 保留原始材料与任务状态，修正归档后的链接，跳过未实现规格的同步，完整需求和后续安排仍可从文档入口查阅
