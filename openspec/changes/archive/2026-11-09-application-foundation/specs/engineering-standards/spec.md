## MODIFIED Requirements

### Requirement: STD-07 报告与证据可追溯

仓库 MUST 在 `reports/` 提供索引、安全基线及检查评审记录，正文包含主题、日期、版本、范围、检查方式、命令、关键输出和实际结论。代码评审表保存于 `docs/verification/code-review.md`，记录适用需求、文件发现与处理要求。公开报告能够独立阅读，相关正文与测试入口通过有效链接关联。完整 JSON、日志和生成报告保存于 Git 忽略的 `.local/verification/`，评测脚本默认使用该目录，并保留显式指定输出位置的能力。同一报告的修改历史由 Git 保存。

#### Scenario: 查阅一次检查

- **GIVEN** 一次文档、工具或运行检查已执行
- **WHEN** 开发者打开正式报告
- **THEN** 能直接查到检查版本、对象、方法、预期、关键输出和实际结论，无须访问本地原始文件

#### Scenario: 更新报告与保护材料

- **GIVEN** 评测脚本生成完整运行记录，调用者未指定输出目录
- **WHEN** 保存结果并整理报告
- **THEN** 原始记录写入 `.local/verification/` 且被 Git 忽略，正式报告保留所需的输出片段和结论，已有本地材料不被整理操作覆盖

#### Scenario: 检查评审与代码审查

- **GIVEN** 安全检查和代码阅读已有实际记录
- **WHEN** 整理检查评审及代码审查文档
- **THEN** 检查评审按明确检查项记录手段、对象、判据与结果；代码审查按文件职责说明依据、发现及结论，同一文件的总体结论保持一致

#### Scenario: 检查主体与覆盖范围

- **GIVEN** 检查包含 AI 阅读、自动化执行或成员核对，原始输出可能含敏感内容
- **WHEN** 编写公开记录
- **THEN** 如实说明实际检查方式和范围，仅保留脱敏后的必要内容，未执行的成员检查保持未完成状态

### Requirement: STD-06 安全检查方法对应产品行为

仓库 MUST 提供身份、数据与接口准备方法，以及未登录、资源隔离、管理权限、直接调用、密钥、依赖和调用追溯七项检查的操作与预期，关联需求编号。权限、并发、事务另有数据副作用和复测依据；公共新闻访问与本人配置保持既定权限，检查不引入额外业务功能。运行条件缺失的项目保持未执行。

#### Scenario: 准备权限与写入检查

- **GIVEN** 已实现的接口与测试身份可用
- **WHEN** 按检查方案准备受保护接口和写入接口清单
- **THEN** 能明确每条操作的身份、对象、请求、响应和数据断言，同时验证合法访问与越权拒绝

#### Scenario: 应用尚未实现

- **GIVEN** 产品需求已明确，但业务接口和运行日志尚不存在
- **WHEN** 整理检查方案与当前结果
- **THEN** 用需求编号和业务能力定位待检查对象，保留前置条件与预期，具体路由及实际结果在实现后补齐，文档核对不记为运行通过

#### Scenario: 准备问答与注入样例

- **GIVEN** 检查需要覆盖材料充分、材料不足和私人上下文隔离
- **WHEN** 阅读检查样例及可选的注入素材
- **THEN** 样例包含输入和预期，公开新闻可正常使用，私人上下文不泄露，可选实验与实际执行状态明确

## ADDED Requirements

### Requirement: STD-08 仓库内容按职责组织

仓库 SHALL 按实际职责组织源码、测试、脚本、文档与运行产物。应用入口负责装配，业务模块和共享能力有明确位置。测试用例与辅助环境分别组织，真实模型评测保持显式执行。文档提供统一导航，业务约定由规格维护，详细说明在对应主题中保存；完整运行输出由 Git 忽略。工具原生配置保留约定入口。

#### Scenario: 查找一个功能的实现

- **GIVEN** 开发者需要维护账号或任务
- **WHEN** 从文档导航及模块目录定位实现
- **THEN** 能找到相关接口、业务实现、测试与说明，共用能力通过明确入口复用

#### Scenario: 调整测试和工具位置

- **GIVEN** 用例、辅助环境或脚本需要调整位置
- **WHEN** 更新文件及命令配置
- **THEN** npm、Make、CI、浏览器与容器入口引用有效路径，原有测试全部被发现，真实模型评测仍须显式启用
