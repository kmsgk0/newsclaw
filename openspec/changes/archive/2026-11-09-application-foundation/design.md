# Design

## Context

NewsClaw 的公共内容和私人阅读资料需要共同的身份、数据库与后台执行基础。应用首先提供可独立启动及验证的账号和任务 API，业务服务使用相同的资源归属与任务合同。

## Goals / Non-Goals

**Goals:** 可复现启动、明确身份、持久接收任务、可恢复执行和可重复验证。

**Non-Goals:** 不拆分额外微服务，不引入组织权限体系或通用调度平台。

## Decisions

### 应用与共享数据模型

Fastify 提供 API，PostgreSQL 保存业务数据，Redis 与 BullMQ 提供队列执行。API 与 Worker 复用运行模块及镜像，应用入口负责装配和启停。

迁移按文件顺序执行，现有迁移文件名和内容保持稳定。共享数据模型预先建立账号、编辑、新闻、会话、技能及专题等表及必要约束。本变更接入账号和任务服务，后续业务在各自模块中接入对应数据表。准备数据结构不触发新闻采集、编辑生成或其他业务处理。

注册在一笔事务中初始化账号与唯一编辑记录。密码使用加盐 scrypt，随机访问令牌仅保存摘要，刷新 Cookie 轮换。登录及密码更新在事务内核对当前密码版本，退出及改密撤销会话。账号和私人任务由服务端校验归属，管理身份不能读取他人的私人任务。

### 任务接收与执行

任务接收将业务写入、任务和 outbox 共同提交，随后向调用方返回任务标识，状态查询通过只读 API 提供。投递循环使用稳定 jobId，数据库保留输入快照及结果状态；队列负责等待、退避及失锁检测。执行标识与投递代次限制旧尝试提交，成功任务重复领取时直接确认。最终失败同时记录待投递死信，管理员只能重放公共任务。

任务运行模块根据已注册的业务处理器分派任务。隔离测试使用受控处理器验证提交、只读查询、重复操作、停机恢复、失锁、最终失败和人工重放；业务模块接入后复用同一套执行资格及提交规则。

### 接口与日志

接口使用统一的 code、message、data 和 requestId，字段错误同时返回具体中文原因及字段映射。错误密码与不存在账号使用相同认证失败提示。请求标识跨进程启动保持唯一，日志保存安全的业务错误原因，不记录凭据、私人正文或外部响应正文。

外部调用在数据库事务外执行，业务、任务及投递记录在必要的短事务内提交。失败不返回成功接收，也不留下半份业务结果。

### 检查和文档

npm 仓库检查覆盖规格、文档、提交引用及安全工具，运行不依赖业务服务或模型。Make、CI 与容器复用同一检查清单，依次执行当前 API 的静态、类型、行为、接口和构建检查，每项执行一次，失败立即停止。账号与任务测试使用隔离数据库、队列和受控替身。

文档导航提供启动、接口、运行和工程规范入口。源码按账号、任务运行及共享能力组织，业务用例与辅助环境分开，真实 HTTP 与进程场景位于 `apitest/cases/`，检查和备份恢复脚本分别维护。

正式报告的格式、版本及证据要求由工程规范定义。完整 JSON、日志和生成输出保存在 Git 忽略的 `.local/verification/`，评测入口允许显式指定其他输出位置。任务状态仅对应本变更已经实现并检查的接口及工具。

## Risks / Trade-offs

队列采用至少一次投递，数据库唯一约束、投递代次和执行资格共同吸收重复执行。数据库已接收而队列暂不可用时，任务保持待投递并在恢复后继续。

## Migration Plan

从配置示例准备运行参数，执行按序迁移后启动 API 和 Worker，管理员凭据由操作者提供。已有数据库只应用尚未执行的迁移。备份恢复脚本在隔离数据库验证账号、任务及关联记录，记录恢复点与耗时；无效备份明确失败并保留当前数据。
