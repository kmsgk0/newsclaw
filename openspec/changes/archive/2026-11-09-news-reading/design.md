# Design

## Context

新闻库提供公共内容，API 使用稳定的报道标识返回原文、摘要、译文、事件与来源。应用基础提供数据库、账号、任务与访问边界。

## Goals / Non-Goals

**Goals:** 保留内容结构和来源，提供忠实中文阅读材料、稳定分类及持续更新，管理员能够处理具体报道失败。

**Non-Goals:** 不建设全网爬虫或独立搜索集群。

## Decisions

### 内容提取与身份

RSS、Atom、JSON 和网页适配器产生统一候选。使用 HTML 解析及 Markdown 转换库提取主体、解析相对链接，保留标题、段落、列表、表格、代码和必要图片。Markdown 来源保留原有结构，不能对整篇内容折叠空白。来源支持正文选择器、抓取全文及领域提示，配置中英文来源。

报道按信源与规范化 URL 更新，内容版本决定派生结果能否复用。新版本只有取得成功结果后才替换已有内容；采集逐条记录失败，其余可处理条目继续推进。单篇重处理复用 collect 任务并携带报道标识及刷新选项。

### 中文整理与事件

语言判断基于实际正文，模型输出使用明确字段，领域映射到统一中文分类。长文翻译按结构分段并校验覆盖范围，保留数字、名称、引用及段落。摘要只说明材料中的事实和不确定性，翻译失败只影响该步骤。

事件候选结合时间、实体与文本相关性，新报道加入后更新概况。事件 API 支持名称检索、分页、来源列表及归属修正，修改后报道与事件查询保持一致。新闻提取出的实体及关系先验证结构与材料依据，图谱查询及专题关系由对应业务接口接入。

### 检索、私人记录与日报

关键词覆盖标题、原文、摘要及译文，语义检索使用 PostgreSQL 向量能力。接口支持来源、领域及稳定分页，非法条件明确报错。收藏和阅读记录按账号与报道去重，状态查询使用同一归属规则。

公共日报按 Asia/Shanghai 业务日期和材料版本组织，采集未完成时等待，内容变化后可以补生成。读取接口返回 items、availableDates、latestDate 与状态。模型读取带 N1 等编号的新闻材料并返回实际使用的编号，宿主校验编号后关联报道，不把处理状态等内部字段传入生成内容。

### 模块与验证

新闻路由、业务、数据访问与内容处理归入新闻模块，信源和模型调用集中在适配器。采集与公共日报处理器接入既有任务服务。隔离用例覆盖结构化长文、重复更新、部分失败、翻译覆盖、分类、事件修正、收藏、历史及日报，模型替身控制生成内容和用量。接口与运行说明同步记录可用命令和参数。

## Risks / Trade-offs

来源结构或可用性变化时，保留已取得内容及具体失败状态。结构和引用校验检查格式及范围，内容事实与翻译完整性还需对照实际材料核对。

## Migration Plan

使用共享迁移已准备的数据表及索引，保持报道标识和收藏关系。备份后启动新闻处理器，以隔离材料验证更新及恢复，不清空已有业务表。
