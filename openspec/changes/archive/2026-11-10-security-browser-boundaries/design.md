# Design

## Context

应用的公共 Fastify 入口对包含 Origin 的 API 写请求校验来源。已有安全测试覆盖身份和资源归属，未对来源校验建立独立回归。课程要求 CSRF token 及 SameSite 证据，需要另行完成，不能把 Origin 检查等同于 token。

## Decisions

使用真实 Fastify 入口及独立的无业务副作用测试路由，检查允许的来源、恶意来源、安全方法和无 Origin 的非浏览器客户端；以处理器调用次数证明拒绝请求没有执行写操作。测试上下文采用最小替身，不连接外部服务。覆盖生产与开发来源差异。复用现有业务测试阶段，不把结构测试伪装成完整 CSRF 实验。

使用 React 服务端渲染实际新闻列表组件，检查恶意标题在生成的 HTML 中转义且不会生成脚本或标签，正常标题仍可读。该检查不替代浏览器中从 API 到实际页面的端到端验证。

真实 HTTP 反例复用隔离 API 环境：对新闻和事件检索发送带 SQL 元字符的无匹配输入，同时以正常词检索作为对照；对本人编辑写入分别发送允许和禁止的 Origin，检查响应与数据库内容，并核对登录响应的 Cookie 属性。浏览器环境插入可通过唯一标识检索的合成恶意标题，测试实际列表 DOM 与文本转义；不改变正常样例的排序。这些检查不宣称已实现单次使用 token。

浏览器写请求在现有 Origin 校验外使用同步器 token。认证用户通过只读、禁止缓存的 `/api/v1/auth/csrf` 取得随机 token，服务端仅保存其哈希、会话及五分钟有效期。刷新令牌 Cookie 同样可用于取得绑定会话的 token，不返回访问令牌或用户信息。写请求原子删除对应会话的 token；过期、重放、跨会话及缺失均拒绝。每次取得 token 独立生成，允许并发写请求；会话删除级联清理，发放时清理过期记录。Origin 存在的认证写请求与所有携带刷新 Cookie 的刷新请求必须校验 token；无 Origin 的 Bearer 客户端不依赖浏览器 Cookie，保留原合同。Origin 拒绝在 token 消费之前执行。

前端对已认证写操作和 Cookie 刷新分别取得 token，保留原有刷新请求去重；令牌失效时刷新会话后取得新的 token 再重试。令牌只在请求期间保存在内存。公开的注册和登录不依赖 Cookie 或现有会话。失败不可重放原 token，必须重新取得。

课程对照记录课程原始链接、项目路径与证据层次，并明确旧报告对应的版本和本次未执行内容。

`make check-security` 顺序复用密钥与依赖阶段、工具行为测试、HTTP 安全反例和桌面浏览器标题反例；失败即退出。PR 安全任务准备隔离 PostgreSQL、Redis 及 Chromium，运行同一命令；完整验收继续从单一清单运行现有应用和浏览器阶段，不添加重复阶段。底层仓库安全扫描单项仍不依赖业务服务。

在一次性容器工作副本临时禁用已消费 token 的拒绝判断，保留 `make check-security` 的失败值和断言；未修改的副本运行同一门禁留存通过记录。实际结果写入 `reports/gate-red-green.md`，未提交版本不虚构修复提交号。

HTTP 审计使用服务端路由模板和方法表示操作，UUID 形态的 `id` 参数表示对象，技能路径可关联技能标识，未取得的技能和用量字段为 null。结果使用实际 HTTP 状态与耗时；不记录查询串、请求体、原始路径值或凭据。模型调用的用量仍由现有技能调用记录关联请求标识保存。自动反例核对合法请求及 401/403/404 记录并检查敏感内容不进入日志；管理员检索和持久化审计另行实现，本范围不声称已完成。

会话读取结果只可写入当前激活的会话：使用当前会话引用核对结果 ID，避免切换期间已经加载或迟到的旧数据重设消息。保留已有请求取消和流式生成边界。复现以真实浏览器的新建、返回会话行为为准。

## Verification

运行新增测试和 OpenSpec 严格校验；条件允许时运行全量验收。验证未执行时保持任务未完成并报告原因。
