# personal-editor Specification

## Purpose
为每位读者提供可配置的个人编辑，结合当前材料和私人阅读记录持续回答问题。日报、手记和可管理记忆共同保存阅读上下文，所有生成结果及其来源按账号隔离。

## Requirements

### Requirement: EDITOR-01 编辑设置与明确兴趣

系统 SHALL 允许修改编辑名字、头像、解读风格和自然语言兴趣，用户明确设置优先于自动推断，无效输入返回具体字段错误并保留原配置。

#### Scenario: 保存与使用
- **GIVEN** 用户拥有编辑。
- **WHEN** 修改设置后重新打开并提问。
- **THEN** 设置持久保存并用于回答及个人日报。

#### Scenario: 无效设置
- **GIVEN** 名字为空或头像地址无效。
- **WHEN** 提交设置。
- **THEN** 返回具体字段错误，保留原配置。

### Requirement: EDITOR-02 材料检索与可追溯回答

系统 SHALL 支持选择新闻、事件或收藏作为材料，也支持跨新闻检索提问；使用 MCP 读取有权访问的材料，引用实际取得的报道，材料不足时如实说明。

#### Scenario: 选择材料并追问
- **GIVEN** 用户有可读的新闻、事件与本人收藏。
- **WHEN** 通过编辑接口选择材料并连续提问。
- **THEN** 接口返回材料名称与范围，引用关联站内报道及原文地址，追问保留上下文。

#### Scenario: 跨新闻查询
- **GIVEN** 问题没有固定对象。
- **WHEN** 检索新闻并回答。
- **THEN** 只使用实际检索结果形成事实与引用，工具失败与没有匹配内容分别处理。

#### Scenario: 材料不足
- **GIVEN** 材料未给出用户所问事实。
- **WHEN** 生成回答。
- **THEN** 说明具体缺口，不编造价格、报道或来源链接。

#### Scenario: 非法或越权工具
- **GIVEN** 工具参数无效或指向另一账号。
- **WHEN** 准备执行。
- **THEN** 服务端拒绝并保留问题，不创建假成功回答，外部内容不能改变执行权限。

### Requirement: EDITOR-03 私有连续会话与流式结果

系统 SHALL 提供新建、重命名、删除及恢复会话，通过 SSE 逐步返回回答。不同会话的数据分别保存，失败可重试且不重复添加同一问题，停止和中断保留实际状态。

#### Scenario: 新建与恢复
- **GIVEN** 用户有已完成对话。
- **WHEN** 新建另一会话、重命名并重新打开原会话。
- **THEN** 两段历史独立，响应包含当前会话标识，原材料及来源恢复，删除只影响本人目标会话。

#### Scenario: 流式阅读
- **GIVEN** 回答正在通过 SSE 输出。
- **WHEN** 接收文本事件或停止请求。
- **THEN** 按顺序返回文本与终态事件，停止后保存真实未完成状态并可重试。

#### Scenario: 失败重试
- **GIVEN** 已有成功消息且最新问题遇到模型或工具失败。
- **WHEN** 重试该问题。
- **THEN** 保留成功消息和问题内容，针对失败回答重新执行，不增加重复用户问题。

#### Scenario: 进程中断
- **GIVEN** 回答未完成时 API 退出。
- **WHEN** 重新启动并打开会话。
- **THEN** 未完成回答可识别且可以重试，不永久阻止发送新问题。

#### Scenario: 空输入与越权
- **GIVEN** 问题为空或会话不属于本人。
- **WHEN** 发送或修改会话。
- **THEN** 拒绝请求，不调用模型、不写入空消息或修改他人记录。

#### Scenario: 失败原因回看
- **GIVEN** 新闻检索或回答生成失败。
- **WHEN** 查看错误、重新查询会话并重试。
- **THEN** 失败消息保留具体安全原因及请求标识，重新查询后仍可读取；重试清除旧错误，成功后返回成功结果，错误不含凭据或外部响应正文。

### Requirement: EDITOR-04 个人日报与阅读回顾

系统 SHALL 按明确兴趣和记忆选择新闻并生成中文导读，缺少兴趣时使用当天内容。日报按本人和业务日期保存，提供最新内容、可用日期及实际状态，同日成功更新仍是一份日报。

#### Scenario: 个性化与历史
- **GIVEN** 用户设置兴趣且当天有相关新闻。
- **WHEN** 生成并回看日报。
- **THEN** 说明新闻与关注方向的关系，来源可打开，日期使用统一业务时区。

#### Scenario: 未填写兴趣
- **GIVEN** 当天有内容但用户未填兴趣。
- **WHEN** 生成日报。
- **THEN** 使用当天新闻并在状态中说明未设置兴趣，不虚构偏好。

#### Scenario: 等待空材料与失败
- **GIVEN** 材料未就绪、无内容或生成失败。
- **WHEN** 查看状态或重新生成。
- **THEN** 返回相应原因及可重试状态，已有成功日报保留，材料到达后可补生成。

### Requirement: EDITOR-05 可管理的长期记忆

系统 SHALL 允许本人查看、新增、修改和删除长期记忆，区分明确填写和自动整理；手动偏好优先，重放已处理活动不能恢复被删除的记忆。

#### Scenario: 管理偏好
- **GIVEN** 用户有自动记忆。
- **WHEN** 修改其中一项并删除另一项。
- **THEN** 后续回答使用修改后的偏好，删除项不再参与个性化。

#### Scenario: 明确设置优先
- **GIVEN** 自动推断与手动偏好冲突。
- **WHEN** 整理新增活动。
- **THEN** 保留明确偏好，不用自动推断覆盖。

#### Scenario: 拒绝越权
- **GIVEN** 记忆属于他人或不存在。
- **WHEN** 访问或修改。
- **THEN** 统一返回不存在且不改变数据。

### Requirement: EDITOR-06 增量阅读手记

系统 SHALL 整理上次成功位置后的阅读、收藏和问答，生成当日手记并补充长期记忆。按实际新增活动形成任务，同日新增活动可更新手记；无新增活动不生成空结果，手记、记忆和处理位置一起提交。

#### Scenario: 连续整理
- **GIVEN** 上午活动已整理且下午新增阅读和问答。
- **WHEN** 调度或本人主动整理。
- **THEN** 只处理新增部分，更新同日手记并保留已整理内容与来源。

#### Scenario: 重复与无活动
- **GIVEN** 当前批次已成功或没有活动。
- **WHEN** 重复执行。
- **THEN** 不重复手记或恢复被删记忆，响应说明没有待整理内容。

#### Scenario: 失败恢复
- **GIVEN** 模型失败或事务提交失败。
- **WHEN** 任务结束并重试。
- **THEN** 不推进处理位置，不提交半份记忆，原手记保留，重试针对同一批材料。
