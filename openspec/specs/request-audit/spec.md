# request-audit Specification

## Purpose
保存脱敏请求及技能调用审计，使管理员能够按操作者、技能、状态和时间回查成功与失败操作，同时防止普通用户读取全局审计数据。

## Requirements

### Requirement: AUD-01 脱敏请求审计

系统 SHALL 保存 API 请求的主体、请求 ID、时间、操作、状态、对象标识和耗时，且不得保存原始路径参数、查询字符串、正文及凭据。审计写入失败 SHALL 产生脱敏错误日志。

#### Scenario: 成功与拒绝请求

- **GIVEN** 请求成功或因身份、权限或资源隔离被拒绝。
- **WHEN** 请求结束且数据库可用。
- **THEN** 保存对应的脱敏记录，并可按请求 ID 查询。

### Requirement: AUD-02 管理员审计查询

系统 SHALL 提供分页的管理员只读审计查询，支持请求 ID、操作者、状态和时间窗口筛选，拒绝匿名和普通用户访问。

#### Scenario: 查询权限

- **GIVEN** 系统保存了审计记录。
- **WHEN** 管理员和普通用户分别请求审计查询。
- **THEN** 管理员可读取脱敏记录，普通用户被拒绝且不能读取记录。

### Requirement: AUD-03 技能调用审计

系统 SHALL 在技能回答完成或失败时，将操作人、时间、操作、对象、结果、技能标识、模型用量、耗时及请求标识写入同一条可查询审计记录；用量不可得时明确为空，不得写入正文或凭据。审计记录与回答最终状态 SHALL 在同一数据库事务中提交。

#### Scenario: 回查成功与失败调用

- **GIVEN** 登录用户调用一项技能，模型调用成功或失败。
- **WHEN** 对应回答保存最终状态。
- **THEN** 审计记录包含与该调用一致的主体、对象、技能、结果、耗时及可得用量。

### Requirement: AUD-04 管理员技能审计筛选

系统 SHALL 仅允许管理员按操作者、技能和时间窗口筛选技能审计；普通用户及匿名用户不得读取全局记录。

#### Scenario: 筛选与权限

- **GIVEN** 两个操作者或技能的审计记录。
- **WHEN** 管理员按操作者、技能及时间窗口查询，普通用户尝试相同查询。
- **THEN** 管理员只得到匹配记录，普通用户被拒绝，查询内容不包含用户正文或凭据。
