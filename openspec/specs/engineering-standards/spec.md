# engineering-standards Specification

## Purpose

为 NewsClaw 开发者提供 AI、数据与评审的共同约定，衔接现有工程规范和检查入口，使开发者能够依据项目需求实施功能、核对相关行为，并准确记录文档和应用的完成状态。

## Requirements

### Requirement: STD-01 规范有明确的读取入口

仓库 MUST 从 README、AGENTS 和开发指南提供工程规范入口；OpenSpec 配置和项目测试技能引导读取与任务相关的规范。共享要求通过引用维护。

#### Scenario: 查找领域规范

- **GIVEN** 开发者已取得仓库
- **WHEN** 准备 AI、数据或评审相关工作
- **THEN** 能从文档入口找到对应约定和检查方式，本地链接有效

#### Scenario: 使用工作流

- **GIVEN** 开发者准备规约或补充测试
- **WHEN** 读取 OpenSpec 指令或项目测试技能
- **THEN** 能取得适用规范，模型相关工作能找到评测样例

### Requirement: STD-02 AI 规范明确核心行为

AI 规范 MUST 说明工具复用既有服务、权限由服务端判断、项目提示词可追溯、新闻引用有实际依据，以及失败时保留成功内容。用户配置与个人技能副本沿用既有产品规则。

#### Scenario: 修改提示词或技能处理

- **GIVEN** 开发者修改项目提示词或技能处理逻辑
- **WHEN** 检查相关改动
- **THEN** 能追溯提示词变更、找到适用样例，既有用户配置及技能选择规则得到保留

#### Scenario: 无效来源与调用失败

- **GIVEN** 输出引用未提供的新闻，或工具越权、模型调用失败
- **WHEN** 对照 AI 规范检查结果
- **THEN** 无效来源不能成为成功成果，越权调用被拒绝，失败明确呈现且已有成功内容保留

### Requirement: STD-03 评测样例有明确预期

仓库 MUST 提供 12 条简明 AI 评测样例，包含需求依据、场景、输入和预期结果，覆盖新闻理解、引用、技能、私人数据及失败情况。样例定义与实际执行结果分别记录。

#### Scenario: 按样例检查行为

- **GIVEN** 开发者查看一条评测样例
- **WHEN** 准备对应功能的检查
- **THEN** 能确定需要的材料、操作和预期结果，并按测试规范选择执行方式

#### Scenario: 功能尚未实现

- **GIVEN** 样例已编写，相关功能尚不可运行
- **WHEN** 查看评测状态
- **THEN** 样例保留未执行状态，不将文档检查记为模型或业务检查通过

### Requirement: STD-04 数据规范保留业务边界

数据规范 MUST 区分公共和私人数据，要求按账号归属访问、迁移随代码管理，并在删除时处理相关数据。取消收藏、删除记忆和撤销分享保持既有业务语义。

#### Scenario: 修改数据结构

- **GIVEN** 开发者调整业务数据结构
- **WHEN** 准备迁移与检查
- **THEN** 迁移随代码保存，说明对已有数据的影响，并验证相关读写和数据关系

#### Scenario: 删除或撤销内容

- **GIVEN** 用户取消收藏、删除自己的记忆或撤销分享
- **WHEN** 检查操作结果
- **THEN** 对应关系或有效读取按需求改变，共享新闻和应保留的私人成果不被误删，其他账号数据不受影响

### Requirement: STD-05 评审与完成条件清楚

评审规范 MUST 提供完成定义和简短检查表，覆盖需求、正常与失败路径、权限、数据及实际检查结果，并复用现有检查入口。核查方法覆盖接口入口、业务逻辑、数据库、公共函数、错误处理、安全隐私和性能；评审按需求覆盖、一致性、失败路径、查询性能、重复逻辑、漏洞风险及高风险场景给出有依据的结论。未实现、失败或未执行的必要检查保持未完成。

#### Scenario: 检查一次变更

- **GIVEN** 一项仓库修改已完成
- **WHEN** 对照检查表与实际 diff 核对
- **THEN** 能判断修改是否符合需求、适用检查是否通过，并说明具体待处理项

#### Scenario: 必要检查未完成

- **GIVEN** 相关行为未实现或必要检查未通过
- **WHEN** 更新任务状态
- **THEN** 相关任务保持未完成，文档和交付说明反映实际情况

#### Scenario: 形成具体评审结论

- **GIVEN** 开发者检查某个文档、工具或业务实现
- **WHEN** 按适用的核查方法和评审维度记录结果
- **THEN** 说明检查对象、规约依据、手段、判据与实际发现，给出可用、待修改或风险无效的结论，未适用项有具体原因

### Requirement: STD-06 安全检查方法对应产品行为

仓库 MUST 提供身份、数据与接口准备方法，以及未登录、资源隔离、管理权限、直接调用、密钥、依赖和调用追溯七项检查的操作与预期，关联需求编号。权限、并发、事务另有数据副作用和复测依据；公共新闻访问与本人配置保持既定权限，检查不引入额外业务功能。运行条件缺失的项目保持未执行。

#### Scenario: 准备权限与写入检查

- **GIVEN** 已实现的接口与测试身份可用
- **WHEN** 按检查方案准备受保护接口和写入接口清单
- **THEN** 能明确每条操作的身份、对象、请求、响应和数据断言，同时验证合法访问与越权拒绝

#### Scenario: 应用尚未实现

- **GIVEN** 产品需求已明确，但业务接口和运行日志尚不存在
- **WHEN** 整理检查方案与当前结果
- **THEN** 用需求编号和业务能力定位待检查对象，保留前置条件与预期，具体路由及实际结果在实现后补齐，文档核对不记为运行通过

#### Scenario: 准备问答与注入样例

- **GIVEN** 检查需要覆盖材料充分、材料不足和私人上下文隔离
- **WHEN** 阅读检查样例及可选的注入素材
- **THEN** 样例包含输入和预期，公开新闻可正常使用，私人上下文不泄露，可选实验与实际执行状态明确

### Requirement: STD-07 报告与证据可追溯

仓库 MUST 在 `reports/` 提供索引、当前安全基线及评审记录，报告包含主题、日期、版本、范围、检查主体和方式、命令、结果及证据链接。详细证据按日期和主题归组，同一报告的修改历史由 Git 保存。公开记录须脱敏；结果只覆盖实际检查对象，AI 检查、脚本运行和协作者复测分别注明来源。

#### Scenario: 查阅一次检查

- **GIVEN** 一次文档、工具或运行检查已执行
- **WHEN** 开发者从报告索引进入正式报告
- **THEN** 能查到检查版本、范围、方法与实际结果，并打开该次工作目录中的相关证据

#### Scenario: 更新报告与保护材料

- **GIVEN** 同一类检查再次执行，输出含本机路径或敏感内容
- **WHEN** 更新报告并整理公开证据
- **THEN** 正式报告记录新的检查版本及结果，历史由 Git 保留，公开材料移除敏感内容并说明脱敏处理，其他工作的材料不被覆盖

#### Scenario: 检查主体与覆盖范围

- **GIVEN** 当前仅执行文档和工具检查，业务运行或协作者复测尚未开展
- **WHEN** 编写评审记录
- **THEN** 标明实际执行方式与已检查对象，将未运行项目留在后续任务中，不将工具结果记为业务或协作者复测结果
