# browser-request-security Specification

## Purpose
保护浏览器来源、会话认证写入、新闻内容及模型回答的安全边界，并通过真实 HTTP、数据库和浏览器反例验证拒绝行为，避免后续修改破坏这些防护。

## Requirements

### Requirement: SEC-09 API 写请求来源检查

系统 SHALL 对带 Origin 的 API 写请求检查服务端允许的来源；不允许的来源 SHALL 被拒绝且不得执行写入处理器。开发环境的本地开发页面与生产环境允许列表分别验证。未提供 Origin 的非浏览器客户端继续遵循身份与输入合同。

#### Scenario: 允许的页面发送写请求

- **GIVEN** 请求来源与配置的应用来源一致。
- **WHEN** 请求向 API 发送合法写操作。
- **THEN** 请求通过来源检查并执行一次处理器。

#### Scenario: 跨站页面发送写请求

- **GIVEN** 请求来源不在服务端允许列表中。
- **WHEN** 请求向 API 发送写操作。
- **THEN** 系统返回 403，写入处理器不执行。

#### Scenario: 开发来源在生产环境不可用

- **GIVEN** 应用运行在生产环境且应用来源不是本地开发地址。
- **WHEN** 本地开发页面发送写请求。
- **THEN** 来源检查返回 403 且处理器不执行。

#### Scenario: 非浏览器客户端与安全读取

- **GIVEN** 合法客户端未发送 Origin，或请求为只读方法。
- **WHEN** 客户端发送 API 请求。
- **THEN** 来源检查不错误拒绝该请求，仍执行适用的认证和输入校验。

### Requirement: SEC-10 新闻标题安全呈现

新闻列表 SHALL 将来源提供的标题作为文本呈现，不能将其中标签或脚本作为页面结构执行；普通标题保持可读。

#### Scenario: 标题包含恶意标签

- **GIVEN** 新闻标题包含脚本标签或带事件处理器的 HTML 标签。
- **WHEN** 新闻列表组件呈现标题。
- **THEN** 生成的 HTML 转义标题中的标签，标题以文本保留，不产生标题注入的脚本或元素。

#### Scenario: 普通标题

- **GIVEN** 新闻具有普通文本标题。
- **WHEN** 新闻列表组件呈现标题。
- **THEN** 用户能够读取该标题及新闻入口。

### Requirement: SEC-11 新闻检索和跨站写入安全回归

系统 SHALL 将检索输入作为数据处理，并在实际 HTTP 与数据库中验证恶意检索和跨站写入的拒绝效果。登录使用的刷新 Cookie SHALL 设置 HttpOnly 和 SameSite=Strict。

#### Scenario: SQL 注入式检索

- **GIVEN** 新闻库与事件库中有正常数据，查询词包含 SQL 元字符和不存在的独有词。
- **WHEN** 通过 HTTP 检索新闻或事件。
- **THEN** 不返回无关对象，不改变数据库；正常词仍能找到相关对象。

#### Scenario: 跨站编辑写入

- **GIVEN** 用户已登录并有本人编辑设置。
- **WHEN** 不允许的 Origin 携带有效访问令牌请求修改设置。
- **THEN** 返回 403，数据库中的设置不变；合法来源可以完成相同操作。

#### Scenario: 刷新 Cookie 属性

- **GIVEN** 登录凭据有效。
- **WHEN** 用户通过 HTTP 登录。
- **THEN** 刷新 Cookie 包含 HttpOnly 和 SameSite=Strict；生产安全 Cookie 配置下还包含 Secure。

### Requirement: SEC-12 单次使用的会话 CSRF token

系统 SHALL 为携带 Origin 的已认证写请求和使用刷新 Cookie 的刷新请求验证与当前会话绑定、短期有效且单次使用的 CSRF token。无 Origin 的 Bearer 客户端保留既有认证合同；浏览器前端 SHALL 在写请求及刷新前取得新的 token。

#### Scenario: 正常与并发写入

- **GIVEN** 同一有效会话分别取得两个 token。
- **WHEN** 两个合法来源的写请求分别使用不同 token。
- **THEN** 两次均可通过 CSRF 检查；每个 token 只生效一次。

#### Scenario: 缺失、重放和跨会话 token

- **GIVEN** 用户拥有有效会话。
- **WHEN** 使用缺失、已消费、已过期或属于另一会话的 token 提交写请求。
- **THEN** 返回 403 且不执行写入。

#### Scenario: Cookie 刷新及会话失效

- **GIVEN** 浏览器只有有效的刷新 Cookie。
- **WHEN** 浏览器取得 token 并刷新会话，之后退出或会话失效。
- **THEN** 刷新成功且旧 token 不可再用；失效会话不能取得可用 token。

### Requirement: SEC-13 HTTP 请求结构化审计

系统 SHALL 为 API 成功和拒绝请求记录请求标识、时间、主体、操作、对象、结果、技能、用量及耗时；不能取得的对象、技能和用量明确记为 null。原始路径参数、查询、请求正文与凭据不得进入请求审计日志。

#### Scenario: 成功及拒绝请求

- **GIVEN** 已准备普通账号、本人资源和其他账号的私人资源。
- **WHEN** 分别发送合法请求、未登录请求、无管理权限请求及跨账号请求。
- **THEN** 记录可关联的成功、401、403 和 404 结果、主体与操作；对象仅记录有效标识，缺失字段为 null。

#### Scenario: 恶意路径与机密输入

- **GIVEN** 未授权请求在路径、查询或正文中包含敏感测试标记。
- **WHEN** 系统记录请求。
- **THEN** 日志仅保存路由模板和经校验的对象标识，不包含敏感标记、令牌或正文。

### Requirement: SEC-14 校验后发布模型回答

系统 SHALL 在完整普通模型回答通过引用检查并保存成功后才向客户端发布回答文本。失败或中断的普通回答不得发布或持久化未校验文本；状态、工具进度与安全错误仍可通过事件流返回。引用检查不能保证事实真实性。

#### Scenario: 模型返回非法引用

- **GIVEN** 模型输出含未提供的来源标识。
- **WHEN** 输出被引用检查拒绝。
- **THEN** 客户端不收到该文本，持久会话中不保存该文本，并收到失败状态。
